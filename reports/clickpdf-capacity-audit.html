ClickPDF: متعدد اور بڑی فائلوں کی جانچ

20 اکتوبر 2026 — اصلاحات اور عملی جانچ کی واضح، جزوی رپورٹ

اہم حد: فائل منتخب ہونا اور مکمل processing کامیاب ہونا الگ باتیں ہیں۔ ایپ میں فائلوں کی تعداد، 500 MB فی فائل اور 1 GB پورے batch کی مقررہ پابندیاں ہٹا دی گئی ہیں۔ اس کا مطلب ہر ڈیوائس پر لامحدود processing یا 1000 MB کی فائل چلنے کی ضمانت نہیں۔ چار ٹولز کے اصل processing انجن نامکمل ملے؛ انہیں کامیاب یا مکمل قرار نہیں دیا گیا۔

کیا درست کیا گیا؟

  • مشترکہ upload validator اب صرف مقررہ تعداد یا سائز کی وجہ سے درست فائلیں رد نہیں کرتا۔ خالی اور غیر متعلقہ فائلوں کی جانچ برقرار ہے۔
  • Merge اور Compress کے ابتدائی object-optimization مرحلے کو الگ Web Worker میں منتقل کیا گیا ہے، تاکہ مرکزی صفحہ زیادہ responsive رہے۔
  • بہت سے اور بڑے documents والے compression batches محدود concurrency یا باری باری چلتے ہیں۔
  • ZIP میں ایک جیسے نام والے نتائج اب ایک دوسرے کو overwrite نہیں کرتے۔
  • بڑے نتائج کے لیے، دستیاب ہونے پر، عارضی browser-local disk cache شامل ہے۔ disk cache نہ ملنے یا quota ختم ہونے پر warning اور memory fallback ہے۔ اس خصوصیت کا عملی browser ٹیسٹ اس جانچ میں مکمل نہیں ہوا۔
  • Batch میں خودکار مسلسل downloads بند ہیں؛ انفرادی نتائج اور ZIP واضح download کارروائی سے حاصل کیے جا سکتے ہیں۔
  • Metadata editor اور analysis میں document selector شامل ہے۔ منتخب ٹول کے اندر Office فائلیں drop ہونے پر صرف PDF/image کی global filtering لاگو نہیں ہوتی۔
  • Repair میں best-effort ساختی rebuild شامل ہے۔ یہ گم شدہ content واپس لانے کی ضمانت نہیں۔
  • Sign، Crop، PDF/A اور Compare میں غلط generic compression fallback ہٹا کر نامکمل engine کی واضح اطلاع اور disabled processing رکھی گئی ہے۔

بڑی فائلوں کے ٹیسٹ: اصل حدود

  • Admission unit tests: 50، 100، 200، 500، 600 اور 1000 MB کے metadata cases منظور ہوئے۔ 150 فائلوں اور 1 GB سے بڑے مجموعی batch کی selection logic بھی جانچی گئی۔ یہ اصل GB-sized documents کی processing نہیں تھی۔
  • حقیقی بڑی فائل: 50,332,894 bytes، یعنی 50.33 decimal MB / تقریباً 48.0 MiB کی valid PDF، جس میں referenced uncompressed RGB image تھی۔ یہ صرف EOF padding نہیں تھی۔
  • Built worker، Node ماحول: بڑی PDF اور دوسری چھوٹی PDF کا merge دو صفحات کے ساتھ درست ہوا۔ ابتدائی compression/optimization worker نے readable ایک صفحے کا نتیجہ دیا۔ optimization output 50,332,545 bytes تھا؛ اس مثال میں نمایاں size reduction نہیں ہوئی۔
  • Browser میں حقیقی 50 MB تا 1000 MB processing: مکمل نہیں ہوئی۔ Browser test connection بار بار منقطع ہونے پر مزید نتائج فرض نہیں کیے گئے۔
  • Regression checks: 9 unit tests، TypeScript check اور production build کامیاب۔

RAM، processor، graphics اور disk

Web Workers processor پر پس منظر کا کام کرتے ہیں۔ وہ RAM کی ضرورت ختم نہیں کرتے۔ PDF کے کئی parsing اور modification کاموں کو پوری document structure memory میں چاہیے ہوتی ہے۔ Graphics acceleration browser کے Canvas/rendering نظام کی دستیاب سہولتوں پر منحصر ہے؛ تمام PDF کام زبردستی GPU پر منتقل نہیں کیے گئے۔ Local disk cache صرف معاون سہولت ہے؛ final ZIP ابھی مکمل memory output بناتی ہے۔ بہت بڑے ZIP کے لیے disk-streaming output اگلا واضح کام ہے۔ کسی document کو server پر خاموشی سے upload کرنے کا راستہ شامل نہیں کیا گیا۔
